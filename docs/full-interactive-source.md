# Full interactive HTTP source preparation

This branch is not a deployed full-parity release. The live bounded reader remains unchanged. Mutations, safe orphan repair, qualified backend artifacts and four native host/provider checks are still required before replacing stdio.

The default semantic profile remains disabled. The existing `namespace-directories-v1` profile keeps its exact namespace-admission and scope-assertion behavior.

The opt-in `resources-directories-v052-v1` search profile requires the exact search-path source revision `7f3ae1af822d936c1d0b070537772b0f1d59122f` and the single operator ceiling `viking://resources`. This identifies the v0.5.2 search contract exercised by the isolated package proof. A changed backend artifact still needs exact source/artifact qualification; this constant does not qualify a patched image or authorize deployment.

Tokens still supply their own signed namespace grants. The profile admits narrower canonical grants beneath the ceiling, preserving the existing file canary. Search requires a directory grant; a file token can read its file metadata but cannot use the parent as a search target. The full resources token can search all its grants or pass an authorized directory as `scope` to narrow the backend target before retrieval, ranking and counts. The legacy profile continues to treat `scope` as an exact-grant assertion.

Search/find send only explicit authorized target URIs with resource context and retain whole-call refusal for an unexpected foreign URI. Archive visibility remains controlled by `include_archived`, including raw ungrouped results. Results are bounded incomplete batches, not an exhaustive inventory or cursor. The resources profile now has bounded filesystem browse paging as described below. Other traversal tools still retain their existing scan limits.

Explicit signed `ov_actions` are checked against scopes. Missing actions mean read-only even if extra scopes were requested. The per-request grant digest includes effective actions and, for the resources profile, its URI policy capability. These checks prepare the mutation authorization boundary; no additional mutation tools are exposed yet.

## Resources browse paging, source only

This paging addition is source-reviewed as part of the read/auth foundation and remains undeployed. Only `resources-directories-v052-v1` adds `offset` to the existing `memory_ls` and `memory_tree` tools. Disabled and legacy namespace profiles retain their catalog, argument schemas and call behavior.

Pass an exact authorized directory URI, or omit it when the token has exactly one directory grant. Multiple grants require an explicit directory to avoid a merged offset with ambiguous authority. Every request checks the current subject's signed grants, expiry and read action. It checks that exact URI with stat before listing. A file-only token receives no ancestor lookup or parent listing. Offsets are plain positions, never authority or a snapshot.

The adapter sends one bounded listing request after that stat. Limits remain 1..100 at the tool boundary, with an effective maximum of 40 paths per page to fit the 49,152-byte MCP output cap even for maximum-length canonical URIs. Offsets are 0..100,000. Follow `next_offset` with the same URI and traversal settings. `has_more` and `truncated` describe that bounded query at the time of the call. At the offset ceiling a further page can be unavailable even when `has_more` is true; `continuation_limited` reports that case. `complete` always remains false. Concurrent insertions, deletions or renames can repeat or omit entries. No snapshot or exhaustive inventory is claimed.

Nonrecursive browse uses `/fs/ls` with explicit name ascending order, original rows, offset and node_limit. Simple ls is deliberately disabled because it erases native denied placeholders before validation. The adapter projects paths only after validating each original row. Recursive ls and tree use `/fs/tree` with original output, explicit offset/node_limit and depth. Recursive ls has depth 12; tree defaults to 2 and accepts 1..12. The tree router has no sort arguments, so its backend default DFS order is retained. Both requests disable abstracts, overviews, tags and hidden files and request no extra fields. The adapter returns only paths and local bounded-page metadata. It discards upstream counts, summaries and arbitrary metadata. It refuses malformed `has_more`, excessive or duplicate entries, foreign or out-of-query URIs, unexpected hidden paths and denied placeholders as a whole call. It never fetches an unscoped global tree and then filters a page.

All three archive names, `archive`, `archived` and `_archive`, remain visible during browse. Ordinary dot directories are valid entries when the typed backend row says they are directories. Hidden files and reserved summaries/locks remain excluded. A response that unexpectedly includes one refuses the whole page rather than silently changing offsets. The resources URI policy now admits the exact UTF-8 read names qualified below. Disabled and namespace profiles keep the original ASCII policy.

Native contract inspected at upstream `7f3ae1af822d936c1d0b070537772b0f1d59122f`:

- `openviking/server/routers/filesystem.py`, ls and tree, forwards visible-node offsets and node limits and returns top-level `has_more`.
- `openviking/service/fs_service.py`, FSService.ls/tree, requests node_limit + 1, emits at most node_limit and derives `has_more`. Simple ls projects full URIs, despite the router description saying relative paths.
- `openviking/storage/viking_fs/_ops.py` and `_access.py`, visible-page listing/tree, apply namespace and native ACL handling before visible offsets. ACL-enabled resources may expose denied name/type placeholders; this adapter refuses them.
- `crates/ragfs/src/core/filesystem.rs` and `cache/wrapper.rs` implement flattened DFS tree offsets, sibling ordering and relative depth bounds. Backend work can rescan earlier visible/raw nodes and read a whole immediate directory internally. The HTTP adapter's request, response and output bounds do not establish a constant backend CPU/memory budget.
- `openviking/core/uri_validation.py`, `openviking_cli/utils/uri.py` and `openviking/utils/path_safety.py` distinguish literal reads from write-target sanitization as detailed below.

Focused paging fixtures cover static listings larger than 256 paths across all pages, roots and subdirectories, depth, archive visibility, per-call request/output limits, invalid offsets and limits, file-only refusal, changed grants/actions/expiry and malformed/foreign/oversized responses. These fixtures and SDK calls qualify adapter behavior only. They are not actual backend execution, production ACL or an inventory proof. Native artifact qualification remains with the root batch.

## Exact resources read URI policy, source only

The root adopted this bounded follow-up for the resources profile. It is source-reviewed as part of the read/auth foundation and remains undeployed. Config derives the closed `resources-utf8-read-v1` Principal policy from `resources-directories-v052-v1`. The default Principal, disabled config and legacy namespace config retain `legacy-ascii-v1` and the unchanged global `canonical` helper. Bearer claims cannot select a URI policy. Verification constructs fresh authority on every request and includes the resources capability in the grant/action digest; the URI capability adds no extra field to the legacy digest. Relative to the deployed base, all digests now include effective actions; no persistent cursor or token-authority cache uses the old digest.

Accepted resources paths have at most 1024 UTF-8 bytes and at most 255 UTF-8 bytes per component. They may contain the existing ASCII name characters, printable non-ASCII characters and embedded ASCII spaces. Each component must be nonempty, different from dot and dot-dot, and free of boundary whitespace. Names are returned and authorized exactly as supplied. NFC and NFD spellings are distinct identities. No Unicode folding, percent decoding, shortening or target sanitization occurs in the adapter.

All percent forms, query/fragment delimiters, backslashes, ASCII colon and variable syntax, other ASCII punctuation outside the legacy name alphabet, control/format characters, Unicode whitespace and malformed scalar values are refused. This includes surrogate code points and joiner-based emoji sequences, while ordinary printable emoji can be literal names. Leading/trailing component spaces and names over 255 bytes remain a precise coverage gap, even where a storage plugin might support them. Literal percent-bearing filenames and broader punctuation are also unqualified. This is not a claim that every arbitrary upstream path is accepted. The inherited natural-sort helper used by nonpaged traversal can also reject accepted Unicode names containing nondecimal digit characters, such as `a1²2.md`: its digit predicate accepts a fragment that integer conversion refuses. Such calls fail safely as unavailable. Native paged browse does not use that helper; broader traversal coverage remains unqualified.

The read identity trace at upstream `7f3ae1af822d936c1d0b070537772b0f1d59122f` is:

- Filesystem/content routers resolve `{namespace:key}` variables before `validate_request_viking_uri`. The adapter forbids that syntax. `validate_viking_uri` strips outer whitespace, then `VikingURI._parse` checks the scheme and scope without sanitizing the path. Namespace resolution strips trailing slashes and supports identity-dependent aliases. Those transformed forms and every non-resources scope are refused here.
- `VikingFS._safe_uri_parts` discards empty path segments and rejects traversal, backslashes and drive prefixes. This policy refuses those inputs rather than authorizing a pre-transformation prefix. `_uri_to_path` is otherwise a literal account-prefix mapping, but `_shorten_component` changes components over the fixed 255-byte limit. Such names are refused instead of copying the shortening algorithm into the adapter.
- `_read_paths` has legacy session fallbacks, which do not apply to resources. `_path_to_uri` preserves spaces. `FSService._read_content` has a missing-file fallback from literal `%20` to a space; literal percent is refused so this fallback is unreachable for accepted paths. Resources stat echoes must match the requested URI exactly. Unexpected raw child URIs now fail closed in resources traversal; legacy child filtering is retained.
- `storage/internal_names.py` reserves `.path.ovlock`, `.redirect.json`, `.sync_log.json` and the `.exact.ovlock.` prefix. Those names and `.relations.json` are refused in resources paths. Browse also refuses `.abstract.md` and `.overview.md`, regardless of a claimed directory type. Explicit abstract/overview reads still use their authorized sidecar paths with no parent fallback.

Write behavior is different. `ContentWriteCoordinator._write` invokes `normalize_storage_target_uri` before its WRITE access check. That helper passes through `validate_safe_viking_uri_path`, then runs `VikingURI.sanitize_segment` on every whitespace-bearing segment. It replaces characters with underscores, merges underscores, strips edge underscores/dots, truncates to 50 characters, defuses Windows device names and substitutes `unnamed` for an empty result. Directory ingestion and tree building also use this normalization. For example, literal read name `meeting notes.md` becomes write target `meeting_notes.md`. The adapter implements no mutation route and does not qualify the read name as a write target. A future writer must authorize the actual normalized target, or refuse any transform, before sending a request. Raw-prefix authorization of the unsanitized input is insufficient.

The UTF-8 fixture tests cover exact byte bounds, static pages over 256 entries in Unicode/space/dot directories, distinct Unicode spellings, changed URI capabilities/actions in signed authority, narrow file reads without ancestors, explicit sidecars, legacy denials, reserved metadata, transformed/foreign response URIs and malformed UTF-8/surrogates without HTTP 500. These remain adapter/SDK fixtures, not execution of the native backend or production inventory proof.

The new SDK tests use a synthetic scoped engine with higher-ranked foreign-store candidates. They demonstrate adapter request and response checks, not real vector execution, production ACL or native interactive acceptance. Exact-image package proof and eventual native acceptance are separate evidence.
